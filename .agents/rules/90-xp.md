# XP, badges and the leaderboard

The gamification layer exists in **two apps** that share storage keys, so a
reader with both installed sees one state. XP is the number that rule matters
most for, and it has already drifted once.

## One ladder, one file

`mobile/src/lib/xp.ts` holds the whole economy — level band, badges, the year
count they are earned against, and what a tick is worth announcing. It mirrors
`src/lib/rewards.ts` in the web app, and `npm run check:xp` reads both and
fails if they part company.

| Number | Value | Web source |
|---|---|---|
| XP per question | 1 | each `question-…` key set to `true` |
| XP per level | **50** (`floor(xp / 50) + 1`) | `rewards.ts` `detectNewUnlocks` |
| XP badges | 10 · 50 · 100 · 250 · 500 · 1000 | `rewards.ts` `XP_BADGES` |
| Streak badges | 3 · 7 · 14 · 30 · 100 | `rewards.ts` `STREAK_BADGES` |

It is one file because it was three. The web levels every 50 questions; the
native card levelled off the *badge* thresholds instead, so **60 XP was level 2
in a browser and level 3 on the phone** — same account, same questions ticked.
Do not add a second copy of any of these constants.

## Three things in `xp.ts` that look arbitrary and are not

- **The count is year-scoped** (`yearXp`). That is what the card calls "Year
  XP", what the badges measure against and what the leaderboard ranks on. A
  global count announces "Bronze Scholar unlocked" over a card still showing
  that badge locked, for anyone who has browsed another year.
- **A milestone is read from the crossing** (`milestoneFor(before, after)`),
  never from a stored list of what has been announced. A count that only goes
  up crosses each threshold once, so there is no bookkeeping to go stale.
- **A badge beats a level** when one tick crosses both. It is the rarer of the
  two and the one with a name worth reading.

## Ticking a question has to say so

`mobile/src/components/XpToast.tsx`, mounted once at the root of `App.tsx` —
like the web's `GlobalCelebrations` — so it fires on whichever screen the tick
happened on. The web has toasted every tick since XP existed; the phone had no
toast component at all, so a tick fed a number you could only find by walking
to My Progress. The reader's verdict on the streak card was "i think it's
fake".

Two behaviours are load-bearing and invisible to tsc:

- **It waits for `isHydrated()` and starts its baseline at `-1`.** Hydration
  loads every question ever ticked in one go; a baseline of 0 reads that as a
  single tick worth four hundred XP and announces it on launch.
- **`pointerEvents="none"`.** It floats over the list people are ticking, and a
  card that eats the next press is worse than no card.

Motion: `Animated.timing` with `EASE.out`, `translateY` + `opacity` only, in at
`DURATION.base` and out at `DURATION.fast`. Timings rather than a keyframe
loop because it can fire twice in a second and must retarget from where it is,
not restart from zero. Reduced motion drops the translate and keeps the fade.

## A reward has to look like one

The four badge tiles under the streak bar were a hairline border on nothing,
the number in `textMuted`, and only the trophy icon changing colour — so on the
black theme an earned badge and an unearned one were the same dim grey
rectangle. Reported as "i cant see anything i think it's fake".

An earned tile is **filled with the accent**, its ink from `onColor` rather
than hardcoded white: amber and cyan accents need black. An unearned tile keeps
`cardElevated` and full-strength text at reduced opacity — it still reads, it
just does not glow.

## The leaderboard shows everyone it fetched

It asks for 50 rows and used to render `rows.slice(0, 10)`, so anyone ranked
eleventh or lower could not find themselves on a board they were on — while the
web app scrolled all 50 in a `max-h-72 overflow-y-auto`. It is a nested
`ScrollView` with `nestedScrollEnabled` (required on Android inside the
Progress screen's own ScrollView) and a bounded `maxHeight`.

Two more things it must keep doing:

- **Identify "you" by `selfId`**, the profile id. Matching on the display name
  highlights a stranger the moment two readers pick the same one, which on a
  board of medical students is not hypothetical. The name is the fallback for a
  reader with no account.
- **Say when the weekly board resets.** "XP earned this week only" is a rule
  with no deadline attached, and the deadline is the reason to open the app
  today rather than on Sunday. The window is Monday-aligned, matching
  `get_weekly_leaderboard`.

## The streak is real, and it is computed on the phone

`mobile/src/lib/streak.ts`, pinned by `npm run check:streak`. It used to read
only `profiles.streak`, which needs a session that a fresh install does not
have — so it showed "0 day streak" for ever. The device keeps its own count
now and the two are merged by taking the larger, which is the only merge that
cannot lose a day someone earned.

`currentValue()` re-checks the stored day against today, so a streak broken two
days ago reads as 0 rather than as whatever it was when it stopped. Reading the
stored number straight back is how a broken streak keeps displaying as unbroken.
